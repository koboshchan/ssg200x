The production custom server is dist/server.mjs, one minified ESM JavaScript file built with pinned esbuild 0.28.2 for Node 24. It contains server.mjs, its runtime modules, Socket.IO and its pure JavaScript transitive dependencies, Clerk backend, MongoDB/BSON and the BIP39 English wordlist actually imported by chat identity. Unused BIP39 APIs are tree-shaken. This is not a bundled Next application. Both Docker entry points start this file; local development still starts the source server.

Next remains external. Its own traced standalone tree, compiled route chunks, static chunks, manifests and required-server-files config remain on disk under .next and node_modules. The complete locked production dependency graph is installed before standalone files are overlaid, because Next route workers have separate external imports and aliases. Bundling the custom server cannot fix missing Next route dependencies. No private keys or environment values are embedded by the bundler.

The generated dist/server-manifest.json inventories every actual external, including Node built-ins, and all bundled inputs. The build rejects unexpected package externals. The sole mandatory non-built-in custom-server external is next. Optional guarded externals are supports-color, bufferutil, utf-8-validate, kerberos, @mongodb-js/zstd, @aws-sdk/credential-providers, gcp-metadata, snappy, socks and mongodb-client-encryption. These optional packages are absent from the lockfile installation. Debug and ws use their normal fallback when their optional accelerators are unavailable. Mongo's optional cloud authentication, Kerberos, SOCKS, client encryption and non-zlib compression are not enabled by this app; enabling them requires installing and testing their packages. No stub implementation is substituted.

CommonJS requires inside the ESM bundle use createRequire. The bundle supplies __filename and __dirname for CommonJS compatibility. Socket.IO's client-dist files are copied to /app/client-dist because its existing client-serving code resolves ../client-dist from the bundled /app/dist directory. The existing /socket.io/socket.io.js endpoint is smoke-tested. JSON data loaded with static requires is embedded. No custom runtime source files are loaded dynamically after bundling; chat-session's literal dynamic import is included in the bundle. Next's dynamic requires and traced package files are intentionally external. MongoDB can still read explicitly configured TLS/OIDC files, but this app does not configure them. Public assets remain in /app/public. Paths to .next build/config/commit files remain anchored to /app rather than moving under dist.

The runner is node:24.22.1-bookworm-slim, Linux x86_64 with glibc, not Alpine/musl. Native image-processing code remains external in sharp 0.35.5 and its matching @img/sharp-linux-x64 and @img/sharp-libvips-linux-x64 packages. There is no argon2 native addon in this dependency graph. SWC is build-only and removed from the runtime image. Do not copy native artifacts between musl/glibc or CPU architectures. The native image smoke test records the actual Node modules ABI, N-API version, glibc and Sharp/libvips versions and performs a real Sharp PNG conversion; those measured values, rather than a guessed ABI, are the release evidence.

Build with npm ci followed by npm run build. Dockerfile performs the source build and production prune. Dockerfile.prebuilt accepts only the allowlisted prebuilt .next output, dist, client-dist, public and package lock/manifests, and installs locked production packages itself. Use Docker BuildKit so Dockerfile.prebuilt.dockerignore is honored. Before accepting either image, run the final image natively against an isolated MongoDB on an identity-verified owned Docker endpoint. scripts/smoke-docker.mjs checks application pages, the client asset, runtime dependency imports, native Sharp and WebSocket upgrade. This packaging check does not replace signed-in production acceptance or exercise optional MongoDB features.
